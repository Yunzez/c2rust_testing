# Reviewed crash-alls (docs/rq4_runbook.md, preflight). ONE root cause, in the C reference itself.
# quadtree 0.1.0's `get_quadrant_` reads `outer->bounds` of a node's four children without checking
# them, and `find_` recurses into it, so any search of a tree that has had NO insert dereferences a
# NULL child. Reaching a non-empty tree needs `quadtree_insert` first -- a SECOND produced object,
# which the frozen bridge does not construct -- so the precondition is unconstructible, not a
# translation defect. Verified 2026-09-07 on both pairs: c-only SEGVs on the empty input,
# rust-only is clean. The newer upstream source the c2rust pair uses added `if(!node) return NULL;`
# to `find_`, which is why only these two pairs carry the entry.

find_
