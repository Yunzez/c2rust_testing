### Which harnesses satisfy the paper's two-stage invariant

Per-record isolated ASan+UBSan C execution **and** a repeat C run: only the six OBS cells (`qsort_c2saferrust` 113, `obs_qsort_ptrtrans` 104, `cjson_ptrtrans` 139, `bzip2_laertes` 529, `tulip_c2saferrust` 202, `crc32_c2saferrust` 65) and the two lil ATTR cells (313 records; in-loop recoverable UBSan-subset flag on the C driver + isolated ASan+UBSan run + alone/fwd/rev stability). These are ablation/witness artifacts. **No headline matrix number is backed by a per-divergence isolated ASan+UBSan replay.** Specifically:

- `cJSON × PtrTrans` 40,133 / 120,050 and `optipng × Laertes` 196,985 / 200,006: single long-lived C process over the whole batch; the "ASan+UBSan on the full corpus: 0 reports" claims are README sentences with no flags or logs archived; the optipng oracle is system libz 1.3.1, not optipng's bundled zlib 1.2.11. The cJSON classes are independently re-established by the OBS cell; the counts are not.
- `qsort × PtrTrans` 34,012 / 50,000: one C process for all 50k records with ASan+UBSan and a whole-batch `assert rc==0` — a batch gate, not a per-record exclusion (clean, so the number stands, but the mechanism is not the one described).
- `bzip2 × CROWN` 29% / 46% / 25% and `bzip2 × Laertes` 91%: validity decided by system `bunzip2` on 150- and 100-record samples; the C batch oracle carried no sanitizer.
- 9 of the 20 manifest defects have Rust-vs-Rust or transcription evidence only, with no C execution at all: C2 (urlparser `url_is_ssh`, base crate under Rust ASan), C3 (lil `do_system`, hand transcription), C4 (bzip2 `endsInBz2`, transcription), C5 (optipng `-dir`), C6/S13 (tulip CLI, two Rust binaries by hand), S1 (crc32 1M sweep; the OBS cell re-establishes it against C on 65 records), S2 (adler32), S4 (crc32 vs system zlib), and the tulip Laertes/C2SaferRust `✓F(150k)` value certificates.
- Certificates: genann 300k/200k/300k, cJSON×c2rust 100k, lil 111,043 ×2, qsort×Laertes 50,827, qsort×SACTOR 10,770, quadtree×CROWN/PtrTrans, lodepng roundtrips — the C oracle, the corpus, or both are gone; the sanitizer configuration is not establishable from disk. They were mostly batch stdin-stream drivers.
- The two generated-harness families the method section describes: `gen_oop_harness.py` produced exactly one RQ4 number (optipng crc32, scratch `h_crc_pipeline/`, gone) and `gen_diff_harness.py --ub-free` exactly one (qsort × C2SaferRust c:1 bridge, crate `pair_qsort` gone; only the target file and the 2-byte trigger survive). Both generators still exist and build.

### Source-version check

Before this audit no harness recorded a hash of the C it executed. The audit fixed identities by sha256 and found: tulip — every C oracle is TI 0.9.2 while all four crates are 0.8.4 build 1537377628 (0.8.4 source now at `tools/frameworks/tulipindicators_v0.8.4`, never bound to a harness); optipng — row mixes 0.7.7 (zlib 1.2.11) and 0.7.6 (zlib 1.2.8), oracle = system libz; cJSON — E3 cell uses a 750-line CRUST-bench copy vs the 1.7.19 reference, and the reference is a re-fetched upstream file (version-string match only); genann — SACTOR consumed a 364-line copy vs the 405-line 1.0.0; lil — 2962-line (CROWN) vs 3518-line (Laertes) sources, and the retracted fn-15 "nondeterminism" was this mismatch; qsort — three textual variants (`int arr[]` / `int*` / commented) across cells, `defect_manifest.md` says "exact-source" for C2SaferRust although the archived file is the `int*` variant. `bzip2` 1.0.8 is unhashed. Determinism checks exist only in the OBS/ATTR cells (12 records); source-version checks exist in 15 records, all version-string or hash-after-the-fact.

### Uncited harness

`tools/tulip_difffuzz` (2026-06-28) is a runnable in-process C-vs-Rust harness over 11 indicators with an archived `ti_adx_start` dropped-dereference finding for C2SaferRust that is absent from `translation_matrix.md` and `defect_manifest.md`; it also shows the base crate has ~4,205 1-ULP bitwise differences (adx/adxr/dx op-order) under strict comparison that the reltol 1e-9 comparison hides.

74 records `build_verified` (retained crates `cargo check` clean on their pinned nightlies; C oracles compile under ASan+UBSan where present), 37 `artifact_missing` (30 cells without a harness + 11 lost workspaces), 2 `not_attempted`, 1 `build_failed` (`bzip2 × PtrTrans`, the documented compile failure). Repo `fuzz/Cargo.toml` for `urlparser_example` still pins the `libafl_libfuzzer 0.15.4` whose build script panics; the ATTR pilot's patched tree lives only in the old ephemeral scratchpad. ## Mode definitions

| mode | meaning |
|---|---|
| `OOP_ASAN_UBSAN` | C reference executed per input in an isolated subprocess built with ASan+UBSan (non-recoverable); Rust runs only after a clean C exit |
| `INPROCESS_UBSAN` | C linked into the fuzz binary; recoverable-UBSan flag gate (`--ub-free`); no ASan in-loop |
| `CUSTOM_SANITIZED_REPLAY` | hand-written driver; every record's C execution runs under ASan+UBSan and exclusions are recorded per record |
| `LEGACY_NO_GATE` | C executed with no in-loop sanitizer check; attribution post-hoc only or absent |
| `MISSING_OR_UNKNOWN` | harness / corpus / C source not on disk, or detector configuration not establishable |
| `REFERENCE_NOT_C` (derived) | differential, but the reference is a base-c2rust crate, a hand transcription, or a third-party implementation — no C execution, so the two-stage invariant cannot apply; the agent's original sanitizer-based label is kept in `_agent_mode` |
| `NOT_DIFFERENTIAL` (derived) | Rust-only fuzz target (E3 reach census) — no reference executed at all |
