Ten C libraries, six translators, one method: run the translation against the original C on the same inputs, gate on ASan/UBSan, and attribute every divergence. A 0-diff is a certificate, a crash is a finding — never a blank. The recurring result: translator correctness is per-library, not per-tool.

Headline findings

#1 · crc32 / adler32semantic

Checksum reset on an empty chunk

C2SaferRust's ptr→slice lift rewrote is_null → is_empty; an empty buffer silently resets the running CRC. 1M-trial differential, end-to-end PNG corruption.

#2 · cJSON parse_stringsemantic

Call-site contract lost

PtrTrans (gpt-5.1): \u escapes always rejected — an empty-slice bound passed at the call site. Callee is faithful alone → only a through-caller differential finds it. 40,133 / 120,050 divergences.

#3 · bzip2crash + semantic

A safety lifter breaks a codec

CROWN's ownership rewrite: 46% silently-corrupt compressed output (BZ_OK returned), 25% heap-corruption crash, default decompress dead. base c2rust byte-exact faithful.

#4 · bzip2semantic

Uncalled init zeroes the CRC table

Laertes lowered BZ2_crc32Table to a runtime init with 0 call sites → all-zero at runtime → 91% wrong-CRC streams. Second independent checksum-corruption instance.

#6 · genannsemantic

The immutable lookup table

SACTOR (gpt-5.1) lifts C's mutable lookup[4096] to an immutable static; the init that fills it writes through a const-cast — Rust UB. Release: every read folds to 0.0 → 100% of inputs return an all-zero network, silently. Its own per-function FFI verification passed all 15 functions.

#5 · qsortsemantic

The sort that doesn't sort

PtrTrans (gpt-5.1) on 30-LOC quicksort: split_at_mut reshaping swaps element 2j−i instead of j; the defensive swap(Option,Option) no-ops on None. Compiles clean, never panics — 68% of arrays come back unsorted.

What the matrix says

bzip2 breaks all five tools

Every non-mechanical tool fails — five ways, at progressively earlier stages. Laertes zeroes the CRC table (semantic), C2SaferRust conflates NULL/empty (crash+semantic), CROWN corrupts memory, PtrTrans won't compile, SACTOR can't even parse it. Only mechanical c2rust is faithful.

Checksum corruption is the dominant class

Three independent instances across two tools. Laertes zeroes any no-rebuild lookup table (bzip2 + optipng CRC); C2SaferRust conflates empty/NULL (crc32). optipng crc32_z is broken by both tools, differently — one function, two silent bugs.

Per-library, not per-tool

CROWN faithfully lifts a 6.6k-LOC PNG codec (lodepng) yet breaks bzip2 — also a codec. qsort, 30 LOC: C2SaferRust crashes, Laertes+CROWN stay correct, PtrTrans doesn't sort — 3 tools, 3 outcomes. The same tool is both reliable and not.

SACTOR: one clean artifact in ten libraries

Its only untouched success is 30-LOC qsort. Recursive cores (cJSON, quadtree, lil) are structurally refused; fn-pointer APIs break its scaffold or parser. And the one real library we pushed through its pipeline (genann, 4 disclosed patches) came out 100% silently wrong — its per-function FFI verification cannot see whole-program bugs.

PtrTrans column complete: a scale cliff

Its three biggest tightly-coupled targets (lil 3.7k, bzip2 7.3k, lodepng 6.6k) ALL fail module assembly — on lodepng where c2rust and CROWN both hold 3036-image certificates. And its only two runnable nontrivial artifacts (cJSON, qsort) both carry silent semantic bugs of the same reshaping-contract class.

Scale defeats CROWN's pipeline

The two largest, most realistic libraries both crash CROWN outright — cJSON (3.2k recursive parser) in rewrite, optipng (~95k codec bundle) in analysis. Its certificates are all on smaller, regular crates. Real-world code at scale defeats the safety lifter.

Discipline shows its work

Exclusions kept false positives out: urlparser's C is itself UB on every URL (library-level — excludes it under Laertes, CROWN and PtrTrans alike); lil's C expr is order-dependent; tulip's 7 suspected utf8 sites = shared wrapper artifact, excluded — but the triage itself uncovered 2 real bugs (guard hoisting segfault + argc off-by-one).
