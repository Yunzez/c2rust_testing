E3 · Case Study · the safety paradox

A safety-lifter left it unsafe.
An LLM made it safe.

The same textbook quicksort, translated C→Rust by six tools. CROWN — a tool whose entire purpose is rewriting raw pointers into safe references — produced code that is 100% still *mut i32. SACTOR, a general-purpose LLM translator, produced fully safe &mut [i32] with split_at_mut. And under our differential fuzzer, all three run at the same depth — safety cost nothing.

The interesting part isn't that one tool won. It's which tool won: the specialist built to remove unsafe couldn't, and the generalist that was never promised to, did — on the simplest possible input, a 30-line quicksort.

01The shared source

One C function. The array comes in as int arr[] — a bare pointer, indexed with a computed j.

That arr[j] with a loop-computed j is the whole story: to lift *mut→&[..] a tool must prove the index is in bounds. CROWN's static analysis can't. The LLM sidesteps the proof by restructuring the code.

03CROWN's own report card

We didn't infer the failure — CROWN's analysis writes it down. From analysis_results/statistics.json:

{   "num_unsafe_ptrs": 4,
  "num_mut_unsafe_ptrs": 4,
  "num_unsafe_usages": 4,
  "num_owning_ptrs_detected": 1
}
→ pointers converted to safe references: 0

Four unsafe pointers in. Four unsafe pointers out.

CROWN's fatness analysis has to decide whether each pointer is a single object (&mut T) or an array (&mut [T]), and prove every access stays in bounds. The computed index arr.offset(j) defeats that proof, so CROWN conservatively keeps the raw pointer. Its only edit is cosmetic: &mut *p → addr_of_mut!(*p). The output is functionally identical to plain c2rust.

SACTOR's borrow-checked slice version runs to the same ~40–49M depth as the raw-pointer versions. The safe rewrite is not slower, not shallower, not harder to exercise — it is simply the same algorithm, minus the pointer footguns. Whatever CROWN gave up by keeping qsort unsafe, it did not buy any depth in return.

05Why this is a case study, not a footnote

◆ The specialist lost on its home turf

CROWN exists to remove unsafe. On the canonical quicksort — the exact kind of array code it targets — it removed none. This is not a corner case; it's the first example anyone would try. Static pointer analysis is brittle exactly where translation is hard: aliasing and computed indices.

◆ The generalist won by restructuring

SACTOR didn't "analyze harder" — it rewrote the algorithm into a shape the borrow checker accepts (split_at_mut for disjoint access). An LLM can change the program's structure; a rule-based lifter can only annotate the structure it's given.

◆ Safety ≠ a performance/coverage tax

A common worry is that idiomatic-safe output is somehow "less real." The depth numbers refute it: the safe version executes just as deeply. Idiomatic and faithful are not on a depth spectrum here.

◆ It sharpens the whole E3 table

Elsewhere the LLM path bites back — SACTOR's genann crash-floors, C2SaferRust crashes whole libraries. qsort is the clean counter-example that keeps the story honest: who wins depends on the tool's mechanism, not its category.

Provenance — every artifact regenerated by the real toolchains, not hand-written. CROWN: nightly-2023-01-26, preprocess→explicit-addr→analyse→rewrite in-place.
