# P3 step 1 — explicit harness schema (2026-06-23)

Replaces adjacency-inferred parameter roles with an explicit, persisted, reviewable schema per
entry (`schemas/<program>.json`), per project-lead P3. This step **only** defines + derives +
persists + validates schemas; it does **not** rewire the generator (step 2) and does **not** add
nested-pointer support.

## What a schema captures

Per parameter: an explicit **role** — `scalar` / `input_buffer` / `inout_buffer` /
`output_buffer` / `out_scalar` / `length` / `capacity` — and a **decode** kind that mirrors the
current generator exactly (`scalar` / `vector` / `derived_from_buffer` / `out_scalar_zero`), plus
the previously-conflated relationships made explicit: a buffer's `length_param` vs an output
buffer's `capacity_param`, and an output buffer's `written_length` (e.g. the return value).

The decode kinds are faithful to the pre-migration generator **on purpose**, so the step-2
generator migration can be proven **byte-identical**. The richer role labels are metadata for
future semantic improvements (e.g. comparing only the written prefix of an output buffer) and do
not change decode bytes yet. `harness_schema.validate()` checks roles, decode kinds, and that all
length/capacity/of_buffer cross-references resolve.

## Derived roles (14 generatable entries)

All 14 derive and validate. Spot-correct: `rle_codec`/`leb128` `dst`/`out` = output_buffer +
capacity; `mergesort_search` `a` = inout_buffer (sorted in place); `rpn_eval`/`tiny_vm`/
`state_machine` out-param = out_scalar; pure-scalar entries (`intmath`, `bitutils`) = all scalar.

## Two latent harness bugs the schema surfaced (the point of doing this)

`const char *` **input strings with no length parameter** were mis-roled by adjacency inference as
`out_scalar` (a pointer with no following integer):

- `glob_match(const char *pattern, ...)` → `pattern` mis-roled out_scalar
- `kv_config kv_parse(const char *line, ...)` → `line` mis-roled out_scalar

Consequence in the current generator: such a param is passed as a pointer to a single zeroed
element — i.e. an **empty string**. So `glob_match` and `kv_config` were being fuzzed with an empty
pattern / empty line and barely exercised. Their `NO_DIVERGENCE_OBSERVED` results are therefore
even weaker than the label implies.

These schemas are left **faithful to current behavior** (out_scalar) to preserve byte-identity for
the step-2 migration; the fix is a dedicated follow-up: add an `input_string` role + NUL-terminated
decode, update those two schemas, and update the generator. That sub-step intentionally **changes**
the decode for `glob_match`/`kv_config` (to actually fuzz them) and is therefore separate from the
byte-identical migration of the other 12 entries.
