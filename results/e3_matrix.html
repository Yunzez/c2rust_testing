Not how much we cover — how deep we hit

Plain fuzzing covers the same code, so breadth showcases nothing. E3 measures depth: the median number of times our differential fuzzer drives each translated Rust function. The tools accept a translation when it compiles — their functions execute 0 times before shipping. Ours drive them 102–108 times. That gap is why bugs survive their validation, and where the translations that can't survive execution reveal themselves.

What the table says

◆ headline The safety paradox — qsort

On one 3-function quicksort, CROWN (a dedicated safety-lifter) kept it 100% *mut i32 while SACTOR (an LLM) produced fully safe &mut [i32] — at identical ~40–49M depth. Safety cost no execution depth. Read the case study →

◆ CRASH-ALL trio corroborates E1

lil / bzip2 / optipng × C2SaferRust fault on all/valid input where the c2rust base runs to full depth. Execution depth independently flags the same three translations E1's differential testing already caught — a second witness for each bug.

◆ tulip vs lil — risk lives in pointers

Same 4 tools, opposite outcomes: the numeric library tulip reaches full depth for all four (173/224, ~27k); the pointer/hashmap/recursion-heavy interpreter lil gives 3 crash-floors + 1 crash-all. Translation risk concentrates in aliasing-heavy code.

◆ Idiomatic can be deep AND safe

PtrTrans quadtree runs 127M-deep and never crashes, while the c2rust base of the same library crashes to a 178k floor. Idiomatic reshaping isn't inherently fragile — it depends on the tool.

Why depth, not breadth

The coverage-% framing died to one objection: plain fuzzing covers everything too. So E3 reports the per-function hit count, not coverage. The claim is causal: the tools accept a translation at 0 executions (it compiles); our bug hunt drives each function 102–108 times. That depth gap is why bugs survive into shipped translations — and the crash-floor / crash-all cells are the translations that literally cannot survive being executed.

Metric caveat: median per-function total-exec (llvm-cov entry count) is loop-inflated but comparable across cells; “reached” counts functions with count>0 — multi-API libraries have unreached families (e.g. optipng's GIF/TIFF readers on a PNG harness). Crash cells fall back to a corpus-replay floor (a lower bound); crash-all cells fault before any depth can be measured — itself the finding.
