## 1. Framing decision — this is a FUZZING paper

**Decided by the user, 2026-08-09.** The paper's contribution is dynamic: differential fuzzing of
shipped C→Rust translations. We may report that the bugs we found **cluster into a few classes**; we may
**not** claim those classes are statically discoverable.

### What this retracts

An earlier draft of the thesis read *"translation failure is systematic and statically predictable."*
The second half is **withdrawn — the evidence does not support it**, for three reasons:

1. **The predicate was fitted, not predictive.** The zeroed-table class was found *dynamically* first
   (E1); the `severed_init` scanner was written afterwards, from those bugs.
2. **Its "validation" is circular.** `bzip2::BZ2_crc32Table` is used as the scan's true positive — but it
   is one of the bugs the rule was induced from. Validating a rule on its own training set proves nothing.
3. **The only genuinely novel predictions are unexecuted.** The 4 silent `snudown` candidates have never
   been run. The scan's precision against unseen data is therefore **unmeasured** — not high, not low.

Additionally, the corpus already contains a documented case where a **static predicate would have been
wrong and dynamic testing was right**: `genann × Laertes` (footnote 16, `results/rq4_effectiveness/translation_matrix.md`).
`laertes_init_lookup` is uncalled — textually identical to the fatal bzip2 CRC pattern — but harmless,
because `genann_act_sigmoid_cached` retains a runtime lazy rebuild (`if !initialized { build }`). Only
execution distinguishes the two. **This is direct evidence for the fuzzing framing and should be in the
paper.**

### The new role of `severed_init_scan.py`

Demoted from *prediction* to **prevalence census**: "the class we found dynamically in 3 tools exists at
139 library sites across the 10 shipped Laertes translations." That is a statement about how much of the
defect class is out there — motivation for dynamic testing, not a substitute for it. See
`results/rq4_effectiveness/severed_init_law.md` (retitle pending: it is a census, not a law).

### What the evidence *does* support

> The same semantic-defect classes recur across independently built translators, and none of them are
> caught by the tools' own acceptance criteria.

Recurrence is real: the zeroed-table *symptom* appears 4× across 3 tools via **3 distinct mechanisms**
(C2SaferRust empty-chunk, Laertes uncalled-init, SACTOR const-cast write). Non-detection is real,
though definitional (`theirs = 0`).

## 2. The core experiment — oracle ablation

The contribution has to land on **oracle design**, not on bug count. Three things distinguish our setup,
and all three are measurable on the corpus we already own.

**Hold the corpus fixed** (20 bugs + 16 certificates), **vary only the validator configuration**:

| # | configuration | detects /20 | false alarms on the certificate cells |
|---|---|---|---|
| 1 | return-value oracle + name-equality alignment (RustAssure-shaped) | ? | ? |
| 2 | whole-program stdout/exit oracle (FLOURINE / ACToR-shaped) | ? | ? |
| 3 | full-state oracle, **UB gate OFF** | ? | ? ← urlparser should blow up here |
| 4 | full-state oracle + UB gate (ours) | 20 | 0 |

Full-state = return value **+** pointer-reachable out-params **+** globals written **+** stdout.

### Why this is the right experiment

- **It is a mechanism-level claim, provable in one table.** Most of our bugs are **state-mutation, not
  return-value**: qsort sorts in place (void return), `BZ2_crc32Table` / zlib `crc_table` / genann
  `lookup` are globals, cJSON `valuestring` is a struct field. A return-value oracle is **structurally
  blind** to them — not "didn't reach it", but "could not see it if it did."
- **It uses the UB gate as a measured discipline, not a stated intention.** Config 3 vs 4 quantifies it
  on `urlparser`, whose C `url_parse` overflows a fixed buffer on *every* valid URL
  (`results/rq4_effectiveness/translation_matrix.md` fn. 12) — and which RustAssure also runs differential symbolic testing on.
- **It gives the three tables a through-line.** Currently any one of E1/E2/E3 can be deleted without
  weakening the others, which is the tell that they are three parallel measurements rather than one
  paper. Under the ablation: E1 becomes the **corpus**, E2 becomes the **alignment axis**
  (name-eq / tool-shipped map / matcher), E3 becomes the **budget axis**.
- **It is cheap and fully in our control.** 38 harnesses already exist; degrading an oracle means
  comparing *less*; the UB gate already has a `--ub-free` switch (commit `9593a1a`). No competitor
  artifact is required, so nothing blocks on someone else's code running.

Estimated 3–4 days, mostly machine time.

**First feasibility check before committing to the full run:** run config 1 (return-value only) against
two *known* bugs — `qsort × C2SaferRust` (void return) and `crc32_z × C2SaferRust` (mutates running
state). If both are missed, the table's main conclusion is already standing and the full sweep is worth
building out.

## 3. PREREQUISITE — normalise the certificates

**This blocks the ablation and is the agreed next item. Chosen: option 2, re-run to a fixed budget.**

### The problem

"Certificate" currently labels a 4-order-of-magnitude range of evidence strengths, all under one `✓`:

| budget | cells |
|---|---|
| `✓F(3036)` | lodepng ×2 ← **weakest** |
| `✓F(100k)` / `✓F(111k)` ×2 / `✓F(150k)` ×2 / `✓F(200k)` | the usable middle |
| `✓F(300k)` ×2 | |
| `✓F(50M)` | genann × C2SaferRust |
| `✓E` ×3 | exhaustive over a **bounded sub-domain** only |

### Why it blocks the ablation

The certificates are the **only** place a false-positive rate can be measured — bug cells give recall,
certificates give precision. But if a degraded oracle reports a divergence on lodepng, a 3,036-record
certificate **cannot distinguish**:

- the oracle is falsely alarming (a true false positive), from
- our own certificate was simply too weak to have found a real divergence.

A cell that cannot tell those apart cannot serve as the referee.

### The work

1. **Re-run every certificate cell to a uniform budget** (proposal: 100k records; lodepng ×2 are the
   mandatory ones, the 111k–300k batch can likely stand as-is). Real coverage-guided fuzzing, per the
   standing rule — no hand-rolled input replay.
2. **Fix the notation and the definition.** `✓E` currently reads as "we proved equivalence." Replace with
   a budget-carrying mark and state plainly:
   > **certificate = no divergence observed at budget N on UB-free inputs. Not a proof of equivalence.**
   `✓E` must also be re-described as exhaustive over a **declared bounded sub-domain** (qsort's is
   len 0–3, values in [−4,4]), not "the whole input domain" as the legend currently claims.
3. **Stratify in the write-up** — report the false-positive denominator only over certificates at or
   above the uniform budget, and list any that remain below it as explicitly non-load-bearing.

## 5. Taxonomy — needs rebuilding, currently a class index

`rq1_bugs_detailed.md:17` has a 6-row class table covering all 20 bugs. It is a **class index, not a
taxonomy**, and will not survive review as one:

- **It mixes cause and symptom on one axis.** S1 is tagged both `NULL/empty conflation` (a *cause*:
  ptr→slice lift rewriting `is_null` as `is_empty`) and `zeroed-table family` (a *symptom*: a value ends
  up zero). Flattening those onto one plane guarantees overlap.
- **The "zeroed-table, 4×, 3 tools" grouping is by symptom.** Those 4 instances arise from **three
  different mechanisms**. That contrast is genuinely interesting — independent tools reaching the same
  wrong state by different routes — but it must be *stated as such*, not presented as one mechanism.
- **No derivation method, no second coder, no completeness argument.** Currently the authors labelled
  their own bugs.
- **No detectability dimension** — which is the one the paper needs, because "the tools' acceptance
  criteria cannot see these" has no precise meaning without it.

**Proposed shape:** rows = **mechanism** (cause), columns = **detectability** (static-visible /
needs-execution / needs-C-side-differential). Symptom (e.g. "zeroed table") becomes a cross-cutting
annotation, not a category. This is pure re-coding of the existing 20 bugs — no runs required — and it
determines what the ablation's configurations should actually be.
